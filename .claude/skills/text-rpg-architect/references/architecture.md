# Архитектура и код

Содержание: 1. Стек · 2. Структура папок · 3. Состояние и цикл ·
4. Контент как данные · 5. Сохранения · 6. Интерфейс · 7. Тесты · 8. Отладка

## 1. Стек

- Если у первой части уже есть стек — используй его. Ниже ориентир для нового кода.
- Клиент: чистый HTML + CSS + JavaScript, без тяжёлых фреймворков.
- Сервер: Node.js + WebSocket, подробности в `coop.md`, раздел 8.
- Игровая логика — в общих модулях, которые работают и на сервере, и в
  node-симуляторе (без DOM). Клиент только отображает и отправляет намерения.
- Никаких внешних CDN и шрифтов из интернета: всё отдаёт свой сервер.
- Одиночный локальный вариант (без сервера, через file://) — только если
  пользователь явно попросит; тогда помни, что ES-модули через file:// в Chrome
  не работают.

## 2. Структура папок

```
client/        — index.html, стили, UI, сетевой клиент
shared/        — игровая логика: состояние, правила, события, бой (сервер + тесты)
server/        — WebSocket-сервер, хранение, снимки, миграции
data/          — контент: ресурсы, постройки, предметы, враги, события, тексты
tools/
  validate.js  — проверка целостности данных
  sim.js       — симулятор баланса
  twoclients.js — тест двух клиентов
deploy/        — скрипт деплоя на VPS, конфиг systemd/pm2 и прокси
.design/       — дизайн-документы (см. SKILL.md)
```

## 3. Состояние и цикл

- Одно дерево состояния `state` (сериализуемое в JSON): ресурсы, постройки,
  жители, герой, инвентарь, карта, флаги сюжета, таймеры, версия сохранения.
- Игровой цикл на `setInterval`/`requestAnimationFrame` с **дельтой времени**:
  при неактивной вкладке и возврате — корректно досчитать (с ограничением).
- Логика отделена от отображения: функции меняют `state`, UI перерисовывается
  по изменениям. Логика должна работать в node без DOM — это нужно для симулятора.

## 4. Контент как данные

Весь текст и контент — в `data/`, движок только интерпретирует. Базовые блоки:

- **Условия:** `{ flag: 'x' }`, `{ resource: 'wood', gte: 10 }`, `{ act: 2 }`,
  `{ building: 'forge' }`, комбинации `all` / `any` / `not`.
- **Эффекты:** добавить/убрать ресурс, поставить флаг, открыть механику/вкладку,
  начать бой, телепорт на карте, вывести строку в журнал, запустить событие.
- **События:** `{ id, trigger, conditions, weight, once, text, choices: [{ text, conditions, effects }] }`.
- **Разблокировки:** каждая механика и UI-элемент имеет условие появления.

Это позволяет писать акты, не трогая движок, и автоматически проверять данные.

## 5. Сохранения

- Хранятся на сервере (см. `coop.md`, раздел 8): автосохранение, снимки
  чекпоинтов, ежедневные бэкапы.
- В состоянии — `saveVersion`. При изменении структуры добавляй миграцию
  `migrate(state)` от старой версии к новой. **Сохранение не должно ломаться
  между обновлениями** — игроки играют параллельно с разработкой.
- Экспорт/импорт состояния файлом — для ручного бэкапа и переноса.
- Наследие первой части (флаги, выборы) импортируется отдельным шагом при
  старте второй части.

## 6. Интерфейс

- Минимализм в духе A Dark Room: моноширинный или сдержанный шрифт, тёмная тема,
  журнал событий с плавным появлением строк, кнопки с полоской перезарядки.
- Интерфейс открывается постепенно — новые панели/вкладки появляются с анимацией.
- Мобильная вёрстка: от 360px, кнопки удобные для пальца, без наведения мышью
  как единственного способа что-то узнать.
- Журнал ограничен по длине (старые строки уходят), важные находки дублируются в кодекс.
- Настройки: скорость текста, размер шрифта.
  Никаких настроек, раскрывающих содержание.

## 7. Тесты

**`tools/validate.js`** — запускать после каждого изменения данных. Проверяет:
- все ссылки по id существуют (предметы в рецептах, враги в зонах, события в эффектах);
- каждый флаг где-то ставится и где-то читается;
- у каждого события достижимы условия (нет мёртвого контента);
- у каждого выбора есть эффект; нет пустых текстов;
- рецепты не образуют цикл, из которого нельзя выйти;
- каждая механика из `systems.md` реально открывается в указанном акте.

**`tools/sim.js`** — симулятор баланса в node:
- бот с простой жадной стратегией проходит экономику акта; выводит время до
  каждого ключевого открытия и до конца акта;
- Монте-Карло боёв (1000+ прогонов) для каждого врага и босса при «ожидаемой»
  экипировке этапа; выводит винрейт и среднюю длительность;
- результаты дописывай в `.design/balance.md` и сравнивай с целями.

**`tools/twoclients.js`** — см. `coop.md`, раздел 9.

Перед отчётом проверь загрузку старого состояния и вёрстку на узком экране.

## 8. Отладка

- Режим разработчика только по параметру URL (`?dev=1`): переход к акту,
  выдача ресурсов, ускорение времени. Не упоминай этот режим и его возможности
  в отчётах — панель выдаёт названия контента.
- Ошибки JS ловить глобально и показывать игроку нейтральное сообщение
  «Что-то пошло не так — опиши, что ты делал» вместо стека с названиями.
