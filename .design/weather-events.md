# Погода и события — оценка (2026-10-23; погода сделана 10-23, события 10-24)

Идея игроков: погода (визуальный оттенок + баф/дебаф) и бытовые события (пример игрока: Сірко
погриз меблі — сам пример не реализовывать).

## Оценка
- Погода: высокая ценность, низкая-средняя цена. Бьёт в «рутина однообразна» и «атмосфера».
  Почти всё есть: `ambient` (snow/fog/marsh… + `overrides` по условию), потреби (`chill`/`wet`),
  `isEvening`, засады, `settleWork`, условия `Cond`.
- События: высокая ценность, цена — в основном контент (10–15 на акт). Риск раздражения, если
  событие = чистая потеря. Правило: каждое событие — маленький выбор или компенсация, потеря ≤ ~10 мин
  рутины, восстановимо, никогда не блокирует сюжет.
- Игроки: вечер < 1 ч → смена погоды раз в 15–25 мин (2–4 за вечер), прогноз на одну вперёд.
  События: не чаще 1 на 10–15 мин на игрока, не в сценах/боях, домашние видят оба.
  Оккультизм у героев/союзников запрещён — в текстах событий никаких обрядов-оберегов.

## Погода — каркас
- `WorldState.weather { kind, since, until, next }`, общая для обоих (кооп), по биомам
  (`AreaDef.sky?: 'open'|'under'` — под крышей/в пещере погоды нет). Генерация в `settle()`
  сидированным rng; веса `WeatherDef.weight` + `when: Cond` (акт, сезон сюжета).
- `WeatherDef { id, name, text, ambient?: AmbientKind, tint?, mods }`, mods — только размен:
  `pace` (actionTime/travelTime), `yield` по `skill`/группе, `ambush`, `chill`/`wet` (потреби),
  `jobs` (жители), `foes` (доп. записи в пулы через условие `{weather}`). Сила ±10–20 %.
- Условие `{ weather: id }` для действий/сцен/пулов/врагов/логов — даёт «редкое при тумане» и т. п.
- Клиент: слой поверх `ambient` (дождь-штрихи, туман уже есть), CSS-переменная оттенка, значок
  в шапке с подсказкой эффекта и «далі: …». Бюджет частиц на телефоне не выше нынешнего.
- Тесты: детерминизм от сида, нет погоды под крышей, sim баланса с худшей погодой, боты игнорируют.

## События — каркас
- `EventDef { id, where: 'home'|'road'|'area', area?, when: Cond, weight, cooldown, once?, text,
  choices?: [{ label, cost?, effects }], effects? }`. Триггеры: tick (дом, раз в N мин),
  `arrive` (дорога), после действия (место). Глобальный кулдаун на игрока + на событие.
- UI: маленькая карточка (`Sheet`) с 1–2 кнопками; без выбора — строка журнала с иконкой.
  Совместные (дом) — оба видят, решает первый, второму — запись.
- Эффекты — существующие (`res`, `flag`, `heal`, `resident`, `perk`, `fight`). Валидатор,
  textscan, языковой тест, боты выбирают первый вариант, автопрохождение без тупиков.
- Связать с погодой: часть событий только при определённой погоде (ливень → протекает крыша …).

## Порядок
1. Погода (движок+клиент+тесты), задним числом в акты 1–2.
2. Каркас событий + ~10 событий на акт 1–2.
3. Дальше — события и погода как часть контента каждого нового акта.
