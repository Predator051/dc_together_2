# События 2.0 (2026-11-02)

Жалоба игрока: события скудные, скучные, «ни о чём», их легко пропустить, их очень мало.
Было: 26 событий (карточка вверху «Тут», легко не заметить; треть — без выбора «нашёл ресурс»).

## Что сделано
- **Показ:** окно поверх игры (`EventModal`, `client/src/events.tsx`), закрыть нельзя — только выбрать.
  Сверху картинка (`client/src/art/events/<id>.webp`, 720×480), текст, выборы с ценой/замком.
  После выбора то же окно показывает **итог** и строку «что дало/взяло» (`EventView.gains`, считает
  сервер из цены и эффектов: ресурсы, здоровье, досвід) — кнопка «Далі». Окно прячется во время сцены,
  боя, сводки и «пока вас не было» и возвращается после. Домашнее — видят оба дома, ответить может
  любой; итог видит ответивший, второй — строку журнала. Слой — над всем (`z-index 29`).
- **Сцены в несколько шагов:** `EventDef.stages` + `EventOutcome.next`. Итог шага показывается сверху
  следующего шага (`lead`). Если исход начал бой — окно закрывается (итог — сам бой).
- **Последствия цепочкой:** исход ставит флаг `evf_*`, другое событие ждёт его (`when`), вес 6.
  Цепочки: 103→104 (вогник → гість), 205→206 (втікач → Білі біля тину), 426→427 (вишня → живець).
- **Частота:** `gap` 9–15 мин (было 15–25), дорога 0,5 (было 0,4), после работы 0,3 (было 0,15).
  Большинство `once`; повторяемые — `again` 4–8 ч. Вес 3 у разовых «сюжетных», 1–2 у повторяемых.
- **Состояние:** `events.open[].stage/lead/done{by,text,gains}`; старые карточки с id, которых больше
  нет, убираются в `settleEvents`. Протокол: `event` с `choice: -1` — закрыть итог.
- **Валидатор:** у шага ≥2 выборов, `next` ведёт в существующий шаг, не в себя, каждый шаг достижим,
  флаги из шагов учитываются. Тест `events.test.ts` (окно, итог, шаги, бой, ≥100), `art.test.ts`
  «painted happenings» (у каждого события своя картинка).
